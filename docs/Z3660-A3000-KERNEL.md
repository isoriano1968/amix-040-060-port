# The A3000 + Z3660 kernel (68060, 128 MB, RTG with soft3D)

How the kernel that runs AMIX entirely on a Z3660 with a real 68060 is built.
It covers the Z3660's 128 MB of CPU RAM, its SCSI and network, its RTG output
with soft3D, and a Hydra AmigaNet card. It's in daily use on an Amiga 3000.

## The machine

- Amiga 3000 with a Z3660 and a real 68060 (rev 6), 128 MB on the Z3660.
- Z3660 preset with `autoconfig_rtg YES`: the board autoconfigures at
  0x50000000, above VSECT1 (1 GB). The drivers reach it through the kernel's
  `dev_kvmap`, not the identity map.
- The AMIX root disk on the Z3660's SCSI (card 1, unit 0), as an HDF on its SD
  card.
- Optional: a Hydra AmigaNet (NE2000, Zorro II).

`config.sh`, as `BUILDING.md` describes it, also names the Z3660 driver
sources:

```sh
Z3660_SCSI_SRC="/path/to/amix-z3660scsi/src/z3660.c"
Z3660_NET_SRC="/path/to/amix-z3660net/src"
```

The Hydra driver source (`hydra.c`, `hydra.h`, `hydrauser.h`, `ne2000.h`)
comes from your AMIX installation (`/usr/sys/amiga/driver/hydra`).

Each relink step stamps a build id. `src/stamp_buildid.py` finds your block of
ids through `git config user.email` in `CONTRACTS.md`, so claim a block there
first.

## The chain

Start from the port's own 68040/68060 kernel, `build/unix-040`, made by
`relink-040.sh`. Then:

```sh
KVSEG_MB=16 sh relink-040-kvseg.sh build/unix-040 build/k-kv16
sh relink-040-serkeep.sh build/k-kv16 build/k-ser
AMIX_ALLOW_UNKNOWN_STOCK=1 sh relink-040-z3660.sh build/k-ser build/k-z3
ZZ9K_CFLAGS="-DZZ9K_FB_NC -DZZ9K_MAP_BOARD" \
  Z3660_RTG_SRC=/path/to/soft3d-z3660rtg-amix/overlay/usr/sys/amiga/driver/zz9000 \
  sh relink-040-zz9000kv.sh build/k-z3 build/k-rtg
HYDRA_SRC=/path/to/hydra sh relink-040-hydra.sh build/k-rtg build/k-hya
sh relink-040-c1hook.sh build/k-hya build/k-con
python3 tools/stamp-rootcard.py --card 1 --unit 0 build/k-con build/k-c1u0
python3 tools/patch-kernel-cacr.py build/k-c1u0 build/unix.z3 0xa0c08000
```

What each step adds:

| Step | |
|---|---|
| `relink-040-kvseg.sh` | A 16 MB kernel virtual segment. The Z3660's 128 MB needs more than the stock size for its page structures. |
| `relink-040-serkeep.sh` | The kernel console mirrored on the serial port, at the speed the boot loader set (`src/serdbg_keepbaud.s`). |
| `relink-040-z3660.sh` | The Z3660's SCSI and Ethernet, mapped through `dev_kvmap`. |
| `relink-040-zz9000kv.sh` | The RTG driver above VSECT1. `ZZ9K_FB_NC` registers the framebuffer noncacheable but not serialised, so the 68060's store buffer speeds up screen writes. `ZZ9K_MAP_BOARD` lets programs map the whole board for soft3D. |
| `relink-040-hydra.sh` | The Hydra AmigaNet. |
| `relink-040-c1hook.sh` | The text console on the RTG output. `zz9k_test /dev/zz9000 redirect` turns it on. |
| `tools/stamp-rootcard.py` | Root and swap on the Z3660's SCSI: card 1, unit 0 (`c8d0s1`/`c8d0s2`). |
| `tools/patch-kernel-cacr.py` | CACR `0xa0c08000`: caches, the 68060's store buffer and the branch cache. These bits exist only on a 68060; use this kernel on a 68060 only. |

For `/dev/paula`, run paula-amix's two steps (`relink-040-audio-paula.sh`,
`relink-040-paula.sh`) after `relink-040-c1hook.sh`, before the root stamp.

## Booting

Copy the result to `/stand/unix.z3` on the AMIX disk. Boot it natively with a
loader that hands over a 68060 ready to run: PCR with the FPU on and
superscalar dispatch, as SetPatch leaves it. The kernel itself never sets PCR.
SORIX-ILOM-LDOM does this, and keeps the serial port's speed for the console.

At boot the kernel reports, among other lines:
- a `zz9000:` line with the board and its address (0x50000000);
- `zz9000: mmap reaches device offset ... (soft3D)`
- the Z3660 SCSI and `zen0`.

Device nodes:
- `/dev/zz9000` (c 49 0)
- `/dev/zen0` (c 51 0)
- with paula-amix, `/dev/paula` (c 53 0)
